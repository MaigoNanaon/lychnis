## 执行规则

- 严格按 TODO 编号顺序实施，同一时间只推进一个 TODO。
- 每个 TODO 必须完成其“实现内容”和“完成检查”后，才能从 `[ ]` 改为 `[x]`。
- 每完成一个 TODO，立即更新本文档的勾选状态和执行记录，再开始下一个 TODO。
- 如果某项连续失败 2 次，停止原策略，改用替代方案；仍无法完成则在该项下记录阻塞原因，不无限重试。
- 实施过程中不顺带修改与当前 TODO 无关的功能。
- 原有曲库、播放、单人游戏、排行榜和分享流程必须持续可用。

### TODO 2 — 实现可复现随机影子

- [x] 完成 Seed 随机影子生成与降级接口

实现内容：

- 新增确定性伪随机生成器，相同 Seed 必须生成相同结果。
- 从现有可计分目标点生成完整点击事件数组。

- 加入基础拟人化特征，避免每个目标点完全独立随机。

完成检查：

- 相同歌曲、谱面版本和 Seed 生成完全一致的事件数组。
- 不同 Seed 能生成不同但合法的事件数组。
- 生成事件均位于歌曲有效时间范围内。
- 无兼容预录影子时可以获得一个合法降级影子。

预计改动文件：

- `js/shadow-generator.js`（新增）

### TODO 5 — 实现单时钟双轨对决引擎

- [x] 完成影子回放、玩家输入和双轨同步

实现内容：

- 页面短时卡顿后影子事件不漏播、不重复。
- 主动结束时音频、动画帧和事件游标被正确清理。

## 已知限制

- V1 使用本地内置影子，不包含真实账号、上传、服务端匹配和跨设备同步。
- V1 只支持 `tap` 点击事件，不处理长按或滑动音符。
- 对手默认使用虚拟角色资料，不宣称是实时真人。
- 对决曲目默认由匹配结果携带，不提供“先选歌再匹配”。
- 当前执行环境未提供 Chromium，因此自动回归覆盖逻辑、资源和 DOM 依赖；最终视觉手感仍建议在真实手机横屏下复核。
